# 无我音乐 1.2.0 播放加载修复

2026-11-07，作者 LHL。最新运行目录：`release/无我音乐-1.2.0-播放修复/win-unpacked`。只提供完整运行目录，不生成新的安装器、单文件包或源码 ZIP；源码在当前工程中。

## 分析结论

本轮没有在外网重复请求中复现用户当时的偶发失败，不能判定当时是哪一台音源服务器或设备出错。代码检查发现以下确定的无限等待和竞争路径，并用受控故障验证修复：

- 浏览器 `audio.play()` 没有启动期限，播放代理没有完整的响应头、首段数据及后续数据空闲期限。网络连接不结束时，界面可能一直加载，原来的加载按钮也不能取消。
- 原版只在界面忽略旧请求，切歌后仍可能等待旧解析和旧音频连接。原生音频桥并发初始化也可能创建不同服务器，旧 HiFi 启动失败可能影响新播放。
- 封面补充、参数探测和历史更新位于播放关键路径，附属请求失败会拖慢或阻塞播放状态更新。
- 接口声明的 FLAC 档位为 2000kbps；它不是测得的文件码率。探测失败时沿用该数字会误导用户判断。

## 修复行为

| 阶段 | 处理 |
| --- | --- |
| 音源解析 | 单次请求 8 秒；继续保留无损 → 320K → 128K 的最高可用音质回退；整次准备最多 35 秒，前端 IPC 等待最多 37 秒 |
| 参数探测 | 最多 2.5 秒，最多读取前 64KiB，FLAC 读到 STREAMINFO 即返回；失败不阻断播放，也不伪造参数 |
| 代理连接 | 响应头最多 8 秒；首段和相邻读取最多 12 秒；连接失败最多尝试两次，必要时重新解析同音质、同格式的临时地址 |
| 浏览器启动 | `play()` 最多 12 秒；启动失败刷新音源再尝试一次；失败后结束加载并显示重试入口 |
| 播放中断 | 监测实际时间是否推进；停止推进约 12 秒或媒体报错时重新解析，尝试恢复原进度；每次手动播放最多自动恢复两次 |
| 取消／切歌 | 加载按钮可以取消；切歌取消旧解析和旧流，旧响应不能清除新音源或停止新的 HiFi 播放 |

各阶段有独立期限，表中的数字不是整个失败流程的总时长。不可用音源、设备不支持、试听或离线等状态仍显示真实原因；不以降低 HiFi 输出要求来掩盖失败。

代理保留实际 Range 和响应头，不再声明服务器未提供的续传能力。错误页面、JSON 和空文件不能当作音频播放。标准播放器和 HiFi 桥共用这一处理。

播放开始后，历史更新和本地资料补充异步执行。封面补齐独立处理。底栏只显示实测或可信的音频参数；未知值保持未知。HiFi 按钮的中性色、无箭头样式保持不变。
