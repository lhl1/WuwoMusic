# 无我音乐 · WuwoMusic

版本：1.2.6 ｜Windows x64 桌面音乐客户端

无我音乐可以搜索、听歌、下载、查看歌词和评论，也支持本地音乐、MV 和 HiFi 输出。无需登录，无需安卓模拟器；界面保留黄色强调色，支持浅色、深色和跟随系统主题。

项目参考交互与请求行为，使用 Electron、React、TypeScript 重新实现桌面客户端。它直接运行桌面代码，不在后台运行 APK。仓库不包含原 APK 或歌曲文件。

> 在线功能依赖第三方服务。已验证代表歌曲和场景，但不能保证整个曲库、所有音质或未来接口一直可用。程序会区分试听、无资源、音质不可用和网络失败。

最新改进：伴奏与伴唱改为本机 AI 分离，保留原声／伴奏／人声预设、连续声伴比例、独立变速与变调，新增准备状态、开关、重试和缓存。准备时继续听原声，完成后保留进度与暂停状态切换。详见 [1.2.6 验证记录](docs/ACCEPTANCE-1.2.6.md) 和 [QQ 音乐研究、实现原理与复现](docs/ACCOMPANIMENT-1.2.6.md)。

## 普通用户如何使用

### 启动与升级

后续每次交付递增版本号，本次为 **1.2.6**。应用、EXE 信息与设置页使用同一版本。

成品采用 **`win-unpacked` 免安装文件夹**。拿到构建包后，解压并双击 **`无我音乐.exe`** 即可，不需要 Node.js、Java 或开发工具。

**移动或分享时必须保留整个文件夹**，不能只复制 EXE，旁边的运行库和 `resources` 都是程序的一部分。GitHub 的 **Code → Download ZIP 下载的是源码**，需要按下面的步骤构建；仓库不提交成品运行目录。

升级时关闭旧程序，换用新版文件夹启动。资料仍保存在 `%APPDATA%\kuwo-desktop`（沿用既有资料目录），收藏、任务、历史和设置会继续保留。旧目录名是为兼容升级而保留的，不要删除它来升级。

### 搜索、播放与评论

1. 顶部输入歌曲或歌手，选联想词，或按 Enter 搜索。支持综合、单曲、歌单、歌手、专辑和歌词搜索。
2. 播放结果中的歌曲。底栏可切歌、拖动进度、调音量、选择音质、播放顺序及队列；底栏不显示倍速，变速在音效面板内调整。
3. 点击封面或歌词入口进入播放页，默认展示唱片封面与同步歌词。列表与歌单卡片封面可悬停放大；底栏封面保持原尺寸。
4. 评论默认隐藏；点击底栏评论按钮，以非线性动画进入歌词页并在左侧阅读。默认按网易云 → QQ → 酷我尝试；平台栏显示可查看、暂无评论、未匹配或暂不可用，可手动切换。空平台不会在后台常驻一个评论模块，手动选择后可以查看其真实状态。读取中途出错会尝试下一平台，并清空上一平台的正文和页码；全部失败保留重试。设置中可修改默认优先平台，自动滚动由单独按钮控制。
5. 自动滚动开启后会展开全文，向下加载新评论，当前分类全部加载完才循环。QQ 的公开热评接口目前仅提供一批约 20 条，热门读完后循环；QQ 最新和网易云评论可以继续分页。悬停、键盘焦点进入、暂停播放、离开页面或隐藏窗口时暂停滚动。

### 新播放器、桌面歌词与伴奏

- 底栏左侧保留封面、歌名、歌手和码率／采样率／位深小框。中央是顺序、切歌、播放、音量和进度；右侧是音质、HiFi、音效、桌面歌词、评论与队列。窄窗口把次要操作放进“更多”。
- 点击底栏封面进入歌词页。右侧在“歌词／歌曲信息／同歌手”间切换：歌词跟随播放，点击一句可跳转；歌曲信息显示当前音频的真实参数，同歌手栏目可直接播放该歌手的其他歌曲。未取得的资料不编造。
- 点击底栏“词”打开独立桌面歌词。默认背景完全透明、位于显示器工作区底部中央，当前行和下一行随播放更新。悬停显示工具条，可播放／切歌、调字号、切换单双行、锁定位置、搜索歌词、开启鼠标穿透及关闭。设置面板可选字体、对齐、加粗、描边、普通／高亮颜色、背景和歌词时间；外观与位置会保存。
- 未锁定时拖动背景移动；穿透后无法点击歌词，请从系统托盘的无我音乐图标解除，或按 **Ctrl+Alt+Shift+L**。**Ctrl+Alt+L** 关闭桌面歌词。高亮按照歌词行时间估算，未伪造逐字时间数据。
- 点击底栏音效图标，选择“伴奏”或“人声”。现在使用本机 AI 模型分离两条独立音轨，支持单声道歌曲；第一次会先准备，期间继续播放原声，完成后保持当前位置切换。滑块左端为人声、中间为原唱、右端为伴奏，预设和开关也可直接使用。支持 0.5–2× 变速、±12 半音变调，速度与音高独立；关闭或恢复原声会使用原音频。失败显示重试；没有准备好时不会伪装成已分离。
- AI 音轨为 44.1kHz / 16bit，分离可能留下混响或伪影；不等于录音棚独立原轨。歌曲不上传，下载文件不改动；HiFi 独占模式使用原文件，旁路声伴、变速和变调。声伴支持 15 分钟以内、512MiB 以内的音源，完成缓存约 32MB/分钟，保存在启动时下载目录的 `.wuwo-cache/stems`，总量优先维持在 2GiB 内；改变下载目录后重启生效。
- 播放队列支持搜索、定位当前歌曲、上下调整、移除、喜欢、下载、清空、存为自建歌单。重启后恢复队列，但不自动开始播放；在自建歌单中可继续使用既有 JSON／M3U8 导入导出功能。

### 查看专辑

点击歌曲的专辑名，或在搜索结果中选择专辑，可查看封面、发行日期、歌曲数量、唱片公司、分类和简介。简介默认两行，点击“展开简介”阅读全文，再点“收起”恢复。未返回的信息不显示空项目。

歌曲的无损、320K 等标签与 VIP、原唱、DTS:X 曲库标记采用一致的小框样式。曲库标记表示服务端有这一标注；底栏的采样率、位深等仍依据实际播放文件，不能据曲库标记推断当前输出。

### 下载歌曲和 MV

- 歌曲菜单或下载按钮可创建任务；列表支持多选批量下载。
- 优先无损 FLAC，没有可用无损时尝试 320K，再尝试 128K。以实际返回文件为准，搜索结果的音质标签不代表该规格必然可用。
- 下载管理可以看进度和速度、暂停、继续、取消及重试；默认并发 3 个任务，设置中可调整。
- 新用户保存到系统 **音乐／无我音乐**，旧用户沿用原目录。设置中可修改保存位置，已有文件不搬移。
- 默认同时保存歌词和封面，重复文件不直接覆盖，文件名自动处理 Windows 非法字符。
- 歌名旁有 **MV** 标记时，可在应用内观看，支持暂停、进度、音量和全屏。MV 可下载为 MP4，保存在音乐下载文件夹，也可离线播放。

### 本地音乐、HiFi 与网络

把音频从资源管理器拖入窗口，即可导入并播放。支持 MP3、AAC、FLAC、WAV、M4A、OGG。优先读取内嵌及旁置歌词、封面，再尝试匹配线上资料；不能可靠区分版本时，不强行绑定其他歌曲的评论或歌词。

鼠标悬停在底栏扬声器图标，或用键盘聚焦它，会弹出竖向音量条及百分比；离开后隐藏。点击图标静音，再次点击恢复，原音量值保持不变；拖动普通模式音量滑块会取消静音。静音也同步到 MV 和 HiFi 引擎。暂停用约 140ms 淡出，恢复用约 180ms 淡入，快速再次操作会取消上一次过渡。

播放器右下方的 **HiFi** 或设置中的“音频输出”，可切换标准播放与 **WASAPI 独占**，并选择设备。HiFi 固定 1× 倍速，正常播放时软件音量为 100%，只在暂停／恢复的短过渡中调整增益，请用设备调音量。设备不支持源文件参数时会显示原因。底栏显示实际音源码率、采样率及位深；音源无损不等于最终硬件输出一定“位完美”。

**默认直连，不使用系统网络代理。** 在 **设置 → 网络 → 网络代理** 可选择“跟随系统代理”，保存后即时应用；不会修改 Windows 代理设置。切换可能短暂中断已有连接。离线模式会阻止应用联网，仍可播放已下载和导入的音乐。

### 歌手页与歌词搜索

点击结果中的歌手名，进入“单曲／专辑／视频／了解 TA”。专辑卡片可打开专辑详情，视频可在应用内播放、下载，简介展示实际返回的歌手资料。各栏目支持分页，返回专辑上一级会恢复原歌手栏目和页码。

只记得歌词时，在顶部搜索一句歌词，再选择“歌词”。结果会显示服务返回的歌词片段，并强调匹配部分。VIP、原唱、DTS:X 都是曲库资料的小标，不据此阻止播放，也不推断硬件输出；仍以实际音源可用性为准。

### 管理本地音乐与自建歌单

- **本地音乐**可导入音频文件或整个目录（含子目录），同一路径去重；导入目录跳过符号链接，单次最多 10000 首。
- 在当前列表搜索歌名、歌手、专辑或文件路径；可按名称、歌手、专辑、时长排序，筛选无损或本地文件。
- “检查文件”检查文件是否还能访问，用“失效文件”筛选查看结果；选择一首本地歌曲后可在资源管理器定位。
- 用每行左侧选择框或表头全选，批量收藏、加入其他歌单、下载、从列表移除。移除只改列表，**保留磁盘原文件**。
- 左侧“自建歌单”旁的加号用于新建；导入按钮可从文件新建歌单。在歌单内可重命名，批量上移／下移（选择“原有顺序”时），删除或增添歌曲。
- **导出 → 无我音乐 JSON** 保存在线歌曲编号与本地文件路径，可在本程序重新导入；不把临时播放链接写进备份。
- **导出 → M3U8** 只导出本地文件，供其他支持 M3U8 的播放器读取；支持导入 UTF-8 的 M3U／M3U8，相对路径以歌单文件目录为准。不会下载歌单文件里的网络链接。
- 导入到当前列表会合并；左侧导入按钮会新建歌单。无效、重复或已经不存在的条目会跳过并提示。本地歌曲依赖实际文件路径，换电脑时需要同时迁移音频并保持或调整路径。

## 从源码复现

### 1. 准备环境与安装依赖

建议使用 **Windows 10/11 x64、Node.js 24、npm 11、Git**。已实测 Windows 10，Windows 11 未做整机验收。

```powershell
git clone https://github.com/lhl1/WuwoMusic.git
cd WuwoMusic
node --version
npm --version
npm ci
```

`npm ci` 根据 `package-lock.json` 安装锁定依赖。首次需要联网下载 Electron，打包也可能下载工具。应用默认直连与 npm 安装时的网络配置是两回事。

若依赖脚本策略导致 Electron 未下载完整，可运行：

```powershell
node node_modules/electron/install.js
```

仓库包含 `build/hifi` 中独立的 mpv 程序、来源说明及对应源码归档。构建当前桌面应用不需要原 APK、jadx、模拟器、登录账号或个人密钥。

### 2. 启动开发版

```powershell
npm run dev
```

这条命令先检查类型、构建，再启动 Electron。目前不是热更新服务器，修改后重新运行即可。开发版也会使用应用资料，验证前建议备份；需要隔离资料时可使用：

```powershell
npm run build
npx electron . --user-data-dir="$env:TEMP/WuwoMusic-dev-profile"
```

### 3. 测试并打包

```powershell
npm test
npm run package:dir
```

输出为 **`release/win-unpacked/无我音乐.exe`**。复制整个 `win-unpacked` 即可在兼容的 Windows x64 电脑运行。

本机已有 Electron 时，可以避免打包工具重复下载运行时：

```powershell
npm run build
npx electron-builder --win dir --x64 --config.electronDist=node_modules/electron/dist
```

这里的“复现”指用相同源码、锁定依赖和步骤构建相同功能，不承诺不同机器生成的 EXE 逐字节一致。`scripts/finalize-*-delivery.mjs` 等交付脚本依赖本机历史备份和 QA 目录，普通构建无需执行。

## 它是如何实现的

### 界面与系统工作分开

可以把程序理解为“前台界面”和“后台管家”。React 负责页面、控件、歌词和播放器；Electron 主进程负责联网、文件、下载、缓存及窗口。界面通过 `preload` 暴露的限定 IPC 接口调用后台，而不是随意读取电脑文件。

启用沙箱、上下文隔离，关闭界面的 Node.js 集成，并验证 IPC 来源、文件路径和图片来源。评论按普通文本渲染，不执行返回的 HTML。见 [main.ts](electron/main.ts)、[preload.ts](electron/preload.ts)。

### 把不同接口整理成统一资料

服务对歌名、编号、图片字段的叫法各不相同。[provider.ts](electron/provider.ts) 将原始响应整理成 [shared.ts](src/shared.ts) 定义的 `Track` 等类型，界面只使用统一格式。

搜索、推荐、榜单、歌单、歌词与评论分别使用相应链路，联想和榜单期数有独立适配。解码处理 UTF-8／GB18030 差异，图片短路径补成完整地址。详细接口表见 [研究记录](docs/RESEARCH.md)。

### 研究 APK，重建所需请求

前期用 jadx 追踪搜索、播放和下载调用，发现改版地址解析还进入原生模块。研究记录保存了运行时载荷和参数证据，再由 Node.js 重建请求：按原链路将参数编码、加密、组合，交给服务器解析临时音频地址。

实现集中在 [provider.ts](electron/provider.ts) 的 `modifiedRequest` 等方法。样本哈希、调用链、分析局限和实际验证见 [RESEARCH.md](docs/RESEARCH.md)。仓库提供桌面实现与记录，不能仅凭源码重新生成当时的原生转储；重新进行原始逆向研究需要同哈希 APK 与对应分析环境。

### 播放时再取地址，避免无限加载

“搜到歌”不代表某种音质一定能播放。点击播放时才重新解析，按无损、320K、128K 尝试，并检查响应。临时地址不当作永久资料保存。

标准播放使用浏览器音频能力，远端音频经受控媒体代理传递，支持进度与取消。解析、连接、首段数据、启动播放都有期限；中断后尝试重新取地址并恢复进度。切歌或取消后，旧请求不能覆盖新歌曲。见 [media-proxy.ts](electron/media-proxy.ts)、[playback-control.ts](src/playback-control.ts)、[App.tsx](src/App.tsx)。

HiFi 使用独立 mpv 进程，通过本机 JSON IPC 控制 WASAPI 独占；在线音频由受控本机音频桥提供，外网访问仍遵循统一网络设置。实际建立独占输出后才显示对应状态。见 [hifi.ts](electron/hifi.ts)、[audio-bridge.ts](electron/audio-bridge.ts)。

### 下载先写临时文件，验证后才完成

[downloads.ts](electron/downloads.ts) 保存任务队列，先写临时文件。服务器支持 Range 时从已有位置继续，不支持或资源改变时重新下载；恢复任务重新解析地址。

完成后用 `music-metadata` 检查实际格式、时长、码率，再移入最终位置。请求 FLAC 却返回低规格文件、试听片段，不能记作完整无损下载。任务持久保存，程序重启后仍能继续管理。

### 歌词、封面与本地匹配

[metadata.ts](electron/metadata.ts) 处理歌词与缓存；[artwork.ts](electron/artwork.ts) 验证图片来源、合并重复请求并缓存图片。已验证的旧图片域名 `img1.kwcdn.kuwo.cn` 统一转换为 `img1.kuwo.cn`，保留原图片路径；API 新数据和旧收藏中的地址都会处理，继续使用 HTTPS 与正常证书校验。歌词首选链路失败时尝试备用接口，不把失败结果作为有效内容长期保存。

本地文件先读取自己的标签、内嵌封面、旁置歌词，再按歌名、歌手、时长、专辑等资料匹配线上歌曲。现场版、翻唱版难以区分时保留本地资料，避免错误关联。见 [local-music.ts](electron/local-music.ts)。

### 新模块如何实现

[artist.ts](electron/artist.ts) 将歌手信息、单曲、专辑和 XML 视频列表转为统一数据。视频使用 APK 的 `music_list + key=mv` 链路，按 artistid 过滤，并以 rid 交给现有 MV 播放器；不使用会返回无关内容的旧搜索方式。[library-tools.ts](electron/library-tools.ts) 负责资料合并、重排、文件扫描及播放列表导入导出。实际文件由主进程弹框选择并重新读取音频元数据，界面通过限定 IPC 调用。

[media-envelope.ts](src/media-envelope.ts) 独立管理浏览器音频的短音量过渡，保留用户设置的音量；每次操作带序号，切歌或快速恢复会让旧过渡失效。HiFi 引擎用相同长度的短增益过渡，正常播放恢复到 100%。这不是歌曲之间的交叉淡化。

### 评论连续阅读

[comment-sources.ts](electron/comment-sources.ts) 先查目标平台的公开歌曲搜索，再比较歌名、完整歌手集合、时长与专辑。现场／翻唱等版本文字保留在标题中，不能只因同名就绑定；有多个难以区分的版本时放弃该平台。网易云有些原版歌曲不能通过公开搜索找到，本版不会硬填旧歌曲编号，会继续尝试 QQ 和酷我。

网易云使用公开 `api/search/get`、`api/v1/resource/hotcomments`、`api/v1/resource/comments`，QQ 使用 `client_search_cp` 与 `fcg_global_comment_h5`，酷我沿用 [comments.ts](electron/comments.ts)。不需要用户登录或提交 Cookie，也不借用本机两款客户端的账号；这里只接入评论，不接入这两家的音频下载。公开接口没有稳定性承诺，变化后需要重新验证。

服务端将评论转成统一格式、标注来源，按歌曲／排序／页码缓存 5 分钟，合并重复请求。正常翻页保持同一来源；源异常切换后从新源第 1 页开始，避免把两家的页码和正文混在一起。三个来源并行查询可用状态，请求合并并缓存；QQ 热评重复分页和连续重复数据会停止加载。业务错误不会伪装成“没有评论”。转义的换行、HTML 字符实体先转成普通文字；常见中文表情转为 Unicode，QQ 原生表情代码使用其实际图片。正文仍按文本渲染，服务端 HTML 不执行。评论图片、表情与头像经过受限代理、大小和格式校验，新增允许实际返回的 `p1`–`p9.music.126.net`、`pic1`–`pic9.y.qq.com`，不开放任意域名。

切歌后清除旧评论并忽略迟到响应。自动阅读展开全文、连续翻页，当前分类没有新内容才循环。状态逻辑见 [comment-feed.ts](src/comment-feed.ts)、[comment-state.ts](src/comment-state.ts)、[Comments.tsx](src/components/Comments.tsx)。

### 桌面歌词和音效怎样工作

[desktop-lyrics.ts](electron/desktop-lyrics.ts) 创建独立、置顶、透明背景的 Electron 窗口，仍使用沙箱和隔离。主界面只传递歌名、歌手、当前／下一行和播放状态，浮窗通过限定 IPC 请求切歌或暂停；只有两个受信窗口的主框架能调用对应接口。默认使用全透明窗口；`desktop-lyrics.json` 第 2 版保存窗口位置、字体、配色、单双行和位置锁定状态，旧版坐标越界时会修正。穿透使用 `setIgnoreMouseEvents`，托盘和专用快捷键负责恢复，关闭后释放这些资源；`queue.json` 保存队列。它们都在原资料目录内。

[vocal-effects.ts](src/vocal-effects.ts) 使用浏览器 Web Audio 将左右声道拆开、按系数混合，切换时短暂平滑过渡。媒体元素使用匿名 CORS，受控 `kuwo://media/随机令牌` 返回对应许可，避免浏览器因跨域保护让处理节点输出静音；原有路径校验与随机令牌仍有效。需要变调时，按需加载 SoundTouch AudioWorklet，在音频线程内处理；无变调时使用浏览器保持音高的原生变速。HiFi 使用独立 mpv，完全绕过这个处理图，并重置比例、速度和音高。相关第三方许可、对应源码和 Source Map 随成品放在 `resources/audio-effects`。

### 统一网络策略

[network-policy.ts](electron/network-policy.ts) 在窗口与业务请求启动前设置 Electron Session：默认 `direct`，用户选择后改为 `system`。播放、下载、搜索、歌词、封面及评论共用此策略。

切换先等待配置生效，再关闭旧连接池，避免继续复用旧代理连接；连续切换按顺序处理，失败尝试回退，不保存未生效的设置。只调整应用会话，不修改系统代理。

## 常见问题

**下载源码后为什么没有 EXE？** 源码需要安装依赖并打包。成品则是完整 `win-unpacked`，二者用途不同。

**加载失败或搜不到歌怎么办？** 检查离线模式与网络；默认直连，依赖代理的网络需手动选择“跟随系统代理”。可取消并重试或换音质。接口失效不能靠重装解决；反馈时请附歌曲名、时间、音质、输出模式及错误提示。

**为什么缺少无损、歌词、MV 或评论？** 服务资源不一致，标签与实际返回也可能不同。程序以真实响应为准，不能获取的内容不会伪造。本地歌曲可靠匹配不到时也不强行关联。

**HiFi 没声音怎么办？** 确认设备可用、没有被占用并选择正确输出；设备需支持源文件参数，也可切回标准模式。HiFi 不会提高原本低质量音源的质量，请用设备调音量。

**如何备份？** 关闭程序后复制 `%APPDATA%\kuwo-desktop`（沿用既有资料目录） 及实际下载目录。程序文件夹、资料目录、下载目录是三个位置；升级不用删除资料。

### 指定独立资料目录测试

可使用标准 Electron 参数 `--user-data-dir` 指向一个已创建的空文件夹，避免测试影响常用资料。例如：

```powershell
& ".\win-unpacked\无我音乐.exe" --user-data-dir="D:\WuwoTestProfile"
```

不传参数时继续使用原有资料。`build/separation` 中的模型与运行组件随包提供，`npm run build` 会核验哈希；源码下载时请保留这些文件。组件、模型和第三方许可详见其中的 `NOTICE.txt`。
